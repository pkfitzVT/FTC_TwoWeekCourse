# Chassis Design Choice SLD

## Session / Course Phase

Day 3, Session 5: First major robot design decision

## Why This Discussion Matters

The chassis is the first subsystem your team will design, build, program, test, and revise. Your chassis does not need to be perfect, but it does need to support your strategy, robot behavior plan, and future shooter/hopper/trigger work.

SLD is the process. The deliverable is the work product that comes out of the discussion.

## Strategy / Behavior / Design Framing

```text
Strategy chooses the game plan.
Robot behaviors describe what the robot must do.
Subsystem designs explain how the robot will do it.
```

Do not design the whole robot today. Design the first working chassis that supports your strategy and leaves room for future subsystems.

The design sequence is:

```text
Demo Robot Design Analysis
-> Game Strategy
-> Robot Behavior Specification
-> Chassis Design Choice SLD
-> Chassis Subsystem Design Template
-> Build / Program / Test / Revise
```

## Main Discussion Question

**Which chassis design best supports our team strategy, robot behavior plan, available materials, and future subsystem needs?**

Simpler version:

**What chassis should we build first, and why is that the best starting point for our robot?**

## What This Discussion Must Produce

By the end of this SLD, complete the chassis section of the Subsystem Design Cycle Template or record enough information to complete it immediately after the discussion.

Your work product should include:

- chassis/frame shape
- material/connector plan
- motor placement plan
- wheel/omni wheel placement plan
- Control Hub placement
- battery placement
- wiring/repair access concerns
- space reserved for shooter/hopper/trigger
- one design feature borrowed from a demo robot
- one design feature modified or avoided from a demo robot
- one tradeoff accepted
- first chassis sketch or diagram
- first chassis test plan

## Evidence / Resources to Use

Use at least three evidence sources. Do not choose a chassis only because it looks cool.

- Demo Robot Design Analysis notes
- Team Strategy Guide
- Robot Behavior Specification
- Chassis shape menu
- Chassis material menu
- Motor placement menu
- Wheel selection menu
- Electronics/battery placement menu
- Design Choice Menu Matrix
- Available materials and parts
- Chassis readings or assembly principles
- SLD tally sheet

## Mini-Decision Rounds

Suggested total time: 20-30 minutes.

| Round | Time | Decision | Evidence to Use | Output |
|---:|---|---|---|---|
| 1 | 3-5 min | What does our chassis need to do? | Strategy Guide + Robot Behavior Specification | Chassis design criteria |
| 2 | 4-5 min | What frame shape should we start with? | Demo Robot Analysis + Chassis Shape Menu | Frame shape choice |
| 3 | 4-5 min | What material/connectors should we use? | Available parts + Demo Robots + Chassis Material Menu | Material/connector plan |
| 4 | 4-5 min | Where should motors and wheels go? | Demo Robot Analysis + Motor/Wheel Menus | Motor/wheel placement plan |
| 5 | 3-4 min | Where should hub, battery, and wires go? | Electronics/Battery Menu + repair access needs | Electronics layout plan |
| 6 | 3-5 min | What space must stay open for shooter/hopper/trigger? | Robot Behavior Specification + future subsystem needs | Reserved-space plan |
| 7 | 3-5 min | What is our first build/test plan? | Subsystem Design Cycle Template | Sketch + first test |

The facilitator should keep the team moving. If the team gets stuck, record the best starting choice and the first test that could prove whether it works.

## Discussion Roles

| Role | Job |
|---|---|
| Facilitator | Keeps the team moving through each mini-decision round. |
| Tally keeper | Uses the SLD tally sheet. |
| Recorder | Writes the chassis decision/work product. |
| Evidence checker | Asks what evidence supports each choice. |
| Space/interference checker | Asks what the chassis might block later. |
| Materials checker | Asks whether the parts are actually available. |

For smaller teams, one person may hold more than one role.

## Sentence Stems

- From the demo robot analysis, we noticed ___.
- Our strategy requires the robot to ___.
- Our behavior specification says the robot must ___.
- This chassis shape helps because ___.
- This frame material makes sense because ___.
- This motor placement helps with ___.
- This wheel choice supports ___.
- This hub/battery placement helps because ___.
- A feature we might borrow from a demo robot is ___.
- A feature we would modify or avoid is ___.
- A tradeoff we are accepting is ___.
- This might make the shooter/hopper/trigger easier or harder because ___.
- Before we finalize, we need to test/check ___.
- I could support this choice if ___.
