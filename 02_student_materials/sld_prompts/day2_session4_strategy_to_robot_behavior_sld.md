# Strategy-to-Robot-Behavior SLD

## Session / Course Phase

Day 2, Session 4: Turning strategy into robot requirements before subsystem design

## Why This Discussion Matters

A strategy does not build the robot by itself. The team needs to translate the game plan into specific actions the robot must perform. Those actions become the design criteria for the chassis, controls, shooter, hopper, trigger, autonomous routine, TeleOp practice, testing priorities, and presentation claims.

SLD is the process. The deliverable is the work product that comes out of the discussion.

## Strategy / Behavior / Design Framing

```text
Strategy = how we plan to play the game.
Robot behaviors = what the robot must actually do.
Subsystem designs = how the robot will do those things.
```

Example:

```text
If our strategy is reliable TeleOp scoring from one position,
then our robot must drive predictably, line up with the goal,
hold artifacts, release/shoot one at a time, and park safely.
```

## Main Discussion Question

**What specific robot behaviors must our robot perform to make our strategy possible?**

## What This Discussion Must Produce

By the end of this SLD, complete or update the Robot Behavior Specification with:

- required autonomous behaviors
- required TeleOp behaviors
- required endgame behaviors
- Must / Should / Could behavior priorities
- performance targets
- first tests for the highest-priority behaviors
- notes about which subsystems must support each behavior

## Evidence / Resources to Use

- Completed Team Strategy Guide
- Modified game rules and scoring guide
- Robot Behavior Specification template
- Game strategy goals menu
- Demo Robot Design Analysis notes about which behaviors seemed easy, hard, reliable, or dependent on driver/operator coordination
- Structure/function reading
- Subsystem design cycle guide/template
- SLD tally sheet

## Discussion Roles

| Role | Job |
|---|---|
| Facilitator | Keeps the team focused on observable robot actions. |
| Tally keeper | Uses the SLD tally sheet. |
| Recorder | Updates the Robot Behavior Specification. |
| Behavior checker | Asks whether each behavior is specific enough to test. |
| Design connector | Asks which subsystem will support each behavior. |

## Sentence Stems

- If our strategy is ___, then our robot must be able to ___.
- This behavior matters because ___.
- This behavior belongs in autonomous / TeleOp / endgame because ___.
- A Must behavior is ___ because without it we cannot ___.
- A Should behavior is ___ because it would help us ___.
- A Could behavior is ___ if we have extra time.
- We can test this behavior by ___.
- The subsystem most responsible for this behavior is ___.
- This behavior will affect our chassis design because ___.
- This behavior will affect our shooter/hopper/trigger design because ___.
- Before we design the subsystem, we need to know ___.
