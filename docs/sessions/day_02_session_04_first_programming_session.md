# Day 2, Session 4: First Programming Session

## Purpose

Introduce how FTC software connects driver input, Java code, configuration names, and physical robot hardware.

## Learning Target

Students can explain how a simple TeleOp program connects the Driver Station, OpMode, hardware map, and robot hardware.

## Success Criteria

- Students identify the OpMode name.
- Students identify hardware names in code.
- Students explain that configuration names must match quoted names in Java.
- Students record one predicted or observed robot behavior.

## Teacher Preparation

Prepare Robot Controller and Driver Station devices, OnBot Java access, example TeleOp code, hardware configuration examples, batteries, safe test blocks, and a safe test area.

## Student-Led Discussion / Decision

Prompt: Why must the names in the configuration file match the names in the program exactly?

## Work Time Options

- Programming: read and annotate the drive-only D-pad and joystick TeleOp examples.
- Testing: run only if hardware is ready and safely lifted.
- Documentation: map hardware names, motor ports, variables, and controls.

## Must / Should / Could

- **Must:** Identify OpMode, hardware names, variables, and gamepad inputs in a drive-only TeleOp.
- **Should:** Make one small documented code or configuration change.
- **Could:** Add telemetry or comments that make the code easier for a teammate to understand.

## Deliverables

- Code notes or screenshot.
- Configuration-name table.
- Test result if hardware is ready.
- Engineering portfolio entry.

## Engineering Portfolio Evidence

Teams should add the OpMode name, configured hardware names, motor ports, gamepad controls, one code change or prediction, and result.

## Reflection / Share-Out

- What part of the code/configuration chain must be correct for safe movement?

## Teacher Notes

Keep first code changes small. Prioritize safe testing and conceptual understanding over driving speed.
