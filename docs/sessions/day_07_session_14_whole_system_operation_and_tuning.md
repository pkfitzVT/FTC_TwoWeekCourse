# Day 7, Session 14: Whole-System Operation and Tuning

## Purpose

Test the robot as a connected system and improve repeatability.

## Learning Target

Students can identify subsystem interactions and choose quick adjustments that improve reliability.

## Success Criteria

- Teams write a repeatable operating sequence.
- Teams run load-fire-reset-reload tests.
- Teams document subsystem interactions and adjustments.

## Teacher Preparation

Prepare field/test area, target, batteries, safety boundary, whole-system test log, and repair materials.

## Student-Led Discussion / Decision

Prompt: Which subsystem worked alone but caused a problem when the whole robot operated together?

## Work Time Options

- Testing: whole-system sequence and integration check.
- Tuning: one adjustment at a time.
- Documentation: sequence, failure point, and result.
- Driver practice: consistent timing.

## Must / Should / Could

- **Must:** Write and test a simple load-fire-reset sequence and identify at least one subsystem interaction.
- **Should:** Improve one reliability issue and document the result.
- **Could:** Run repeated trials and calculate success rate.

## Deliverables

- Whole-system test log.
- Operating sequence.
- Quick adjustment record.
- Engineering portfolio entry.

## Engineering Portfolio Evidence

Teams should add sequence tested, what worked, what failed, subsystem interaction evidence, adjustment made, and next step.

## Reflection / Share-Out

- What quick adjustment helped, and what would a stronger permanent version look like?

## Teacher Notes

Temporary fixes are for learning, not final safety solutions. Watch for wires, battery movement, servo strain, and unsafe driver timing.
