# Student-Led Discussion Support Coverage Matrix

## Purpose

This matrix audits whether each major student-led discussion prompt has enough student-facing support for students to participate with evidence, make a decision, and document the result.

Ratings:

- **Strong:** Students have prompt + background + decision/documentation support.
- **Adequate:** Students have enough to proceed, but support could be clearer.
- **Partial:** Some support exists, but students may need more structure.
- **Missing:** Discussion exists, but no clear student-facing support document was found.
- **Unclear:** More review needed.

This is an audit document only. It does not rewrite existing prompts or create missing instructional materials.

Reusable support now available: `90_templates/student_led_discussion_tally_sheet_template.md` can be used with any 5-10 minute student-led design discussion to track participation, evidence use, decision synthesis, and growth over time. `docs/design_choice_menu_matrix.md`, `02_student_materials/decision_menus/demo_robot_design_analysis_activity.md`, and `02_student_materials/decision_menus/demo_robot_design_observation_activity.md` connect those discussions to concrete design-choice deliverables.

For a session-by-session table that pairs each official SLD prompt with a concrete deliverable, discussion type, evidence/resources, and notes/gaps, see `docs/sld_prompt_deliverable_table.md`.

## Highest Priority Gaps

1. **Mechanism architecture lacks decision-menu support.** Shooter, hopper, trigger, and servo sessions have readings and test prompts, but fewer structured decision tools than chassis and controls sessions.
2. **Strategy-to-behavior transition needs protected class time.** Student-facing SLD sheets now exist for the Team Strategy Guide and Robot Behavior Specification, but teachers still need to protect time for both before chassis decisions.
3. **Chassis decision sequencing now has a student-facing structure, but teachers still need to protect time.** The Chassis Design Choice SLD sequences the menus into mini-rounds; implementation risk is rushing teams straight into building.
4. **Testing artifacts could be more standardized.** Shot logs, hopper jam logs, trigger position test sheets, and match/practice evidence sheets would help teams convert discussion into comparable evidence.
5. **Later-session standalone SLD sheets are still limited.** Day 1 Session 1, Day 2 Session 3, the Day 2 strategy/behavior bridge, Day 3 chassis design, and both Day 3 Session 6 control discussions now have standalone student-facing SLD sheets, but most later discussions still rely on teacher-facing session pages or decision menus. High-value mechanism design, testing, and presentation discussions could use student-facing SLD sheets.
6. **Final presentation rehearsal support is adequate but not polished.** Notebook pages and readings exist, but a rehearsal checklist or role card would make Session 19 easier to run.
7. **Some engineering notebook session references are still TODO or generic.** These should be resolved as new student-facing support documents are created.

## Notes

- The matrix treats `docs/sessions/` as the teacher-facing session source and `01_session_plans/` as shorter planning mirrors.
- Static site coverage means the source material is already included by the site generator. This audit did not rebuild the static site because no site navigation was changed.
- A discussion can be rated **Strong** even without a standalone SLD sheet if students have a reading, decision tool, notebook/template support, and teacher-facing facilitation notes.
